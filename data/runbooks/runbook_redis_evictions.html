RB-207: Redis Memory Pressure and Evictions

Serviceredis-cache (Redis 7.2, Sentinel: redis-cache-01 primary, redis-cache-02/03 replicas)
SeveritySEV-3 (SEV-2 if the public-api hit ratio drops below 85%)
OwnerData Platform team
Last reviewed2026-08-11

1. Symptoms

  • Alert RedisMemoryHigh fires when used_memory is above 90% of maxmemory for 10 minutes.
  • Alert RedisEvictionsHigh fires when evicted_keys grows faster than 500 keys/s for 5 minutes.
  • The cache hit ratio falls and public-api latency rises (the "cold cache" case in RB-415).

2. Memory configuration

Each redis-cache host has 32 GB of RAM. maxmemory is 24gb and maxmemory-policy is allkeys-lru: when the limit is reached Redis evicts the least recently used keys, whether or not they have a TTL. The remaining 8 GB is headroom for the fork done by background saves (copy-on-write) and for the OS.

3. Diagnosis

3.1 Read INFO memory

redis-cli -h redis-cache-01 -p 6379 INFO memory
redis-cli -h redis-cache-01 -p 6379 INFO stats | grep -E 'evicted_keys|keyspace_hits|keyspace_misses'

The fields that matter:

used_memory_human
Memory used by data; compare with maxmemory_human.
mem_fragmentation_ratio
Above 1.5 means fragmentation, not real data growth.
evicted_keys
Cumulative count; take the rate over 1 minute.

3.2 Find big keys

Run the scan on the replica redis-cache-02, never on the primary:

redis-cli -h redis-cache-02 --bigkeys -i 0.1
redis-cli -h redis-cache-02 MEMORY USAGE "<KEY>" SAMPLES 0

A single key above 100 MB (usually a report:* hash or a feed:* list) is a bug in the writer.

3.3 Find keys without a TTL

INFO keyspace prints keys= and expires= per database. If fewer than 80% of keys in db0 have an expiry, a writer is storing keys without a TTL. Sample them with redis-cli --scan --pattern 'session:*' --count 1000 and TTL <KEY> (-1 means no TTL).

4. Remediation

4.1 Raise maxmemory temporarily

for h in redis-cache-01 redis-cache-02 redis-cache-03; do
  redis-cli -h "$h" CONFIG SET maxmemory 26gb && redis-cli -h "$h" CONFIG REWRITE
done

26gb is the ceiling on 32 GB hosts. Set it on all three hosts so a Sentinel failover does not bring back the old limit.

4.2 Defragment or remove big keys

If mem_fragmentation_ratio is above 1.5, run CONFIG SET activedefrag yes. For an oversized key, get the owning team's approval and delete it with UNLINK <KEY>, which frees memory in the background instead of blocking like DEL.

Warning: never run FLUSHALL, FLUSHDB or KEYS * on redis-cache in production. KEYS * blocks the single Redis thread for seconds, and flushing empties the cache so every request falls through to orders-db at once. Use SCAN with COUNT 1000 instead. Do not switch the policy to noeviction either: writes then fail with OOM command not allowed.
