RB-801: Database Credential Rotation with Vault

ServiceVault database secrets engine (mount database/) for orders-db
SeveritySEV-2 (SEV-1 if credentials are known to be compromised)
OwnerSecurity team, with the Data Platform team
Last reviewed2026-09-30

1. Symptoms

  • Alert VaultLeaseRenewalFailed fires when more than 10 lease renewals fail in 5 minutes.
  • PostgreSQL logs password authentication failed for user "v-k8s-orders-app-rw-...".
  • Pods log FATAL: role does not exist shortly after a lease has expired.

2. How dynamic credentials work

Applications never hold a fixed database password. The vault-agent sidecar requests credentials from role orders-app-rw, which creates a PostgreSQL user with default_ttl = 1h and max_ttl = 24h. The agent renews the lease before it expires and renders the result to /vault/secrets/db-creds. After 24 hours a brand new user is issued, and the app must reload the file.

3. Diagnosis

3.1 Inspect the leases

vault list sys/leases/lookup/database/creds/orders-app-rw
vault lease lookup database/creds/orders-app-rw/<LEASE_ID>
vault read database/roles/orders-app-rw

A lease with ttl close to 0 and no renewals points to a stuck vault-agent.

3.2 Check the vault-agent sidecar

kubectl -n orders logs deploy/orders-app -c vault-agent --since=30m | grep -i -E "error|renew"

permission denied means the Kubernetes auth role orders-app lost its policy. If the agent renders new credentials but the app still fails, the app is not reloading /vault/secrets/db-creds; it must reload on SIGHUP.

4. Remediation

4.1 Force new credentials for one app

vault lease revoke -prefix database/creds/orders-app-rw/<LEASE_PREFIX>
kubectl -n orders rollout restart deployment orders-app

Restarted pods get fresh credentials from vault-agent on startup. Restart in batches of at most 25% of the pods.

4.2 Rotate the root credential

The connection orders-db uses the PostgreSQL user vault_admin to create users. Rotate it after any suspected exposure:

vault write -f database/rotate-root/orders-db

Afterwards only Vault knows the vault_admin password. Data Platform must confirm that no human, script or backup job logs in as vault_admin before you run it.

Warning: do not run vault lease revoke -prefix database/creds/ on the whole mount during business hours. It drops the database users of every application at once and causes a full outage until each pod has restarted.
